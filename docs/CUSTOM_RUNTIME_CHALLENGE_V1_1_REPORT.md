# LangGraph 与自研 Runtime 冻结对比报告

## 结论

透明事故恢复协议 v1.1 已完成一次有效正式运行。自研 Runtime 在同一24条冻结 Challenge 上
严格通过24/24，约束违反为0；LangGraph 冻结基线同为24/24。主指标差为0，自研 Runtime 在
本任务集上保持了 LangGraph 的正确性，但没有准确率提升，也不能由此证明跨领域泛化。

必须同时披露：此前 v1 已建立账本，但因非 ASCII 凭据在本地 Authorization header 编码阶段
失败，模型调用与 provider 尝试均为0。v1 原始0/24永久保留但不是能力结果；本次 v1.1 使用同一
24条任务，属于透明事故恢复，证据强度低于一次未中断的原始预注册运行。

## 安全探测

新账本前先执行固定的非 Challenge 缺参请求：只进行1次 provider 尝试，HTTP 200，返回预期的
`finish/needs_clarification`；探测声明 Challenge 加载数和运行数均为0，且不记录凭据。探测
通过后才创建 v1.1 `running` 账本。

## 逐任务配对

- 24/24终止状态相同；
- 24/24成功配置匹配；
- 24/24工具轨迹逐字节相同；
- 15/24最终 answer 逐字节相同；其余差异来自澄清或停止消息措辞，全部通过冻结答案契约；
- 模型调用数差0、Prompt tokens差0、严格通过数差0。

自研运行总耗时比 LangGraph 低约10.3%，P50低约6.6%，P95低约16.9%。由于两次正式模型运行
发生在不同时段且网络等待占主导，这些端到端差异不能归因于 Runtime 架构。

独立的500组无模型离线配对显示，LangGraph 本地路径中位数6.210 ms，自研 Runtime 0.295 ms，
比值约21.06×，配对绝对差约5.898 ms。这个结果支持“自研调度路径更轻”，但5.9 ms只占真实
单任务秒级耗时的很小部分，不能表述为端到端加速21倍。
