# Offline Stability / Soak Test Report

## Scope

This is a deterministic, no-model, no-network Runtime scheduling test. It does
not measure end-to-end Agent latency and does not establish an online SLA.

## Configuration and actual result

| Field | Value |
|---|---|
| Requested minimum | 5,000 runs **and** 1,800 seconds (later condition wins) |
| Executed runs | 2,783,807 |
| Scenarios | normal, clarification, one semantic recovery, persistent fail-closed |
| Reporting interval | 500 runs |
| Unexpected exceptions or results | 0 |
| Inconsistent results | 0 |
| Missing traces | 0 |
| Expected outcomes | 1,391,904 success; 695,952 clarification; 695,951 tool error |
| Duration | 1,800.000642 s (30 minutes) |
| Sampled local scheduling P50 / P95 / max | 0.657550 / 1.089800 / 1.903700 ms |
| Last steady checkpoint / peak | 53,389 / 134,768 bytes |

Evidence: `artifacts/qa/stability_30min.json` and its 5,567 checkpoint records
in `artifacts/qa/stability_30min.progress.jsonl`, generated by
`scripts/run_stability_test.py`.

## Memory interpretation

The script keeps only a bounded 512-entry latency sample, forces collection at
each checkpoint and writes progress incrementally to JSONL so its own reporting
storage cannot grow with run count. The final steady checkpoint at 2,783,500 runs
was 53,389 bytes versus a 134,768-byte peak. This is a lightweight local signal,
not a leak proof or process-RSS benchmark.

## Verdict

**PASS WITH KNOWN LIMITATIONS.** The pass criterion was met for deterministic
behaviour, expected terminal states and trace completeness. It does not cover
real LLM long-running calls, GUI, high concurrency, distributed workers or
production traffic.
